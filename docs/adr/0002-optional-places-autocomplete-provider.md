# Optional Place Autocomplete Provider Architecture (Google Places v1 + OSM Photon Fallback)

Map & Posters remains a zero-backend, offline-capable single-file application (`index.html`) with an unchanged `Project` v1 schema; optional place autocomplete is implemented in a pure client module (`src/places-search.ts`) that defaults to OpenStreetMap Photon (`https://photon.komoot.io/api/`) with no API key required and upgrades automatically to Google Places API (New, v1: `places:autocomplete` plus `places/{id}` details on selection) whenever the user saves an optional API key in browser `localStorage` (`map-and-posters:google-places-key`). Storing the API key exclusively in `localStorage` — never in `Project`, IndexedDB `projects`, or exported JSON backups — ensures users can freely share or archive trip backups without leaking credentials and keeps backup validation strictly v1-compatible. Both providers receive a padded GPX bounding box derived from the active route (`bbox` + `lat`/`lon` for Photon, with center-biased fallback if strict `bbox` returns zero results; `locationBias.rectangle` for Google Places v1) so short place names resolve locally along the user's trip rather than globally, while every network, HTTP, or storage failure degrades into a non-blocking status message so manual coordinates, map links, and offline editing always work without interruption. For Step 2 (`Split into days`), resolved coordinates are snapped deterministically onto interior points of the active day's GPX track via `snapPlaceToRoute`, clustering contiguous in-range points into distinct passes so out-and-back routes reuse the existing `Matching visits` pass selector and require explicit confirmation via `Split here`.
